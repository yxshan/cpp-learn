# `<charconv>`

`<charconv>` 提供数字与连续字符区间之间的低层转换。接口不分配字符串、不依赖区域设置，
也不用异常报告普通转换失败。

## 快速信息

- 头文件：`<charconv>`
- 命名空间：`std`
- 首次标准：C++17
- 核心错误通道：结果对象中的 `std::errc`

## 直接包含

```cpp
#include <charconv>
```

不要依赖 `<string>`、格式化库或框架头文件偶然传递包含 `<charconv>`；首次使用这些声明前应直接
包含其所属头文件。

## 设施与方向

| 方向 | 代表设施 | 调用者提供 | 结果 | 首次标准 |
|---|---|---|---|---|
| 字符 → 数字 | `from_chars` | `[first, last)` 与目标对象 | 停止位置 `ptr`、错误码 `ec` | C++17 |
| 数字 → 字符 | `to_chars` | 可写的 `[first, last)` | 写入尾 `ptr`、错误码 `ec` | C++17 |
| 浮点格式 | `chars_format` | scientific/fixed/hex/general 选择 | 控制解析或格式化形式 | C++17 |
| 结果类型 | `from_chars_result`、`to_chars_result` | — | 轻量指针与错误码对象 | C++17 |

整数与浮点重载均进入 C++17 标准，但不同标准库的历史实现进度可能不同。本项目用当前本机
工具链实际编译验证整数示例。当前草案中的后续 `constexpr`、新增结果转换或更晚重载不能视为
C++20 基线。

## 关键合同

- 区间不需要空字符结尾。
- `from_chars` 不跳过前导空白；整数正值默认不接受前导 `+`。
- 成功只表示解析了一个合法前缀；要验证完整消费，仍需检查 `ptr == last`。
- `to_chars` 不附加空字符；调用者根据返回指针构造结果视图。
- 输出缓冲区不足以容纳完整表示时返回 `errc::value_too_large`。

## 选择边界

协议、配置和高频日志路径需要明确区间、无区域设置和无异常错误分支时使用 charconv。普通 UI
格式化若更重视可读模板、宽度和对齐，可选择更高层格式化设施。

## 常见错误

- 忘记检查 `ec`，直接使用目标值或输出区间。
- 只检查成功，不检查是否完整消费输入。
- 认为解析会跳过空白或接受所有 `strtol` 语法。
- 把输出缓冲区当作自动增长的 string。

## 与 JavaScript 的区别

> JavaScript 的 `Number()`、`parseInt()` 返回 Number，并通过 `NaN` 等值表达部分失败；
> charconv 把目标数值类型、输入边界、停止指针和错误码显式交给调用者，也不会自行分配字符串。

## 相关内容

进入 `std::from_chars` 和 `std::to_chars` 查看每个方向的完整错误模型。拥有文本使用 `<string>`，
借用区间使用 `<string_view>`。
