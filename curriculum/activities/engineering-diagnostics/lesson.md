# Git、静态分析与性能剖析闭环

工程诊断需要一条证据链，而不是凭感觉改代码。先用小而可回滚的 Git 提交保留实验边界；回归出现时用测试和 bisect 缩小引入范围；编译器告警与 clang-tidy 发现局部风险；最后用采样 profiler 或显式计数确认热点。

本练习不只要求写说明：CMake 会以 warnings-as-errors 编译 app 与测试，CTest 会在隔离目录创建 good/bad 两个真实 Git 提交并执行 `git bisect run`。程序还要给线性扫描增加确定性的比较计数，`PROFILE.md` 与 `BISECT.md` 则保存能由门禁复核的结论。

计数不能替代生产采样，但它能固定复杂度假设，并为不同实现提供同输入对照。生产 profiling 还应记录构建版本、输入规模、工具版本与采样方式，避免只贴一张无法复现的火焰图。

修复性能问题后仍要回到测试与静态分析，确认优化没有扩大未定义行为或破坏可读性。

## 练习要求

补全线性扫描、profile/bisect 工件，并让严格告警、真实 Git fixture、CTest 与 Judge 输出共同通过。

完成后回答反思题，并说明失败 mutation 破坏了哪个边界。
