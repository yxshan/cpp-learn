# `std::priority_queue`

`std::priority_queue<T>` 维护一个堆，每次 `top()` 都观察当前最高优先级元素。默认比较器
`std::less<T>` 让最大元素位于顶部，而不是最小元素。

## 快速信息

- 头文件：`<queue>`
- 命名空间：`std`
- 标准：C++98 起
- 默认底层容器：`std::vector<T>`

## 什么时候使用

事件调度、Top-K、最短路径候选或随时取得当前最佳任务时适合 priority queue。若必须按到
达顺序处理，使用 `std::queue`；若需要搜索任意元素、修改中间元素或稳定迭代全部内容，
priority queue 的受限接口并不合适。

它不提供“降低某个已有元素优先级”的句柄操作。算法可选择重复压入新候选并在弹出时丢
弃过期项，或采用支持句柄更新的其他堆结构。

## 代表性声明

```cpp
template<class T,
         class Container = std::vector<T>,
         class Compare = std::less<typename Container::value_type>>
class priority_queue;
```

常用操作为 `top()`、`push()`、`emplace()`、`pop()`、`empty()` 和 `size()`。底层容器需要
随机访问迭代器并支持 `front()`、`push_back()` 与 `pop_back()`。

## 比较器语义

`Compare(a, b)` 为 `true` 表示 a 的顺序排在 b 之前；priority queue 把按该顺序“最后”的
元素暴露在顶部。因此默认 `less` 得到最大堆，而 `greater` 得到最小堆。这一点常与“返回
true 表示更高优先级”的直觉相反。

比较器必须形成严格弱序。若多个元素等价，容器不保证它们按插入顺序弹出；需要稳定次序
时，把单调序号作为显式的次级比较键。

## 复杂度与返回值

`top()` 为常数复杂度。默认 vector 底层的 `push`/`emplace` 包含摊销常数追加与对数堆修
复，因此总体为摊销对数复杂度；`pop` 的堆修复为对数复杂度。由一整个范围构造时可利用建
堆，而不是逐次插入的简单等价成本。

`top()` 返回 const 引用，不能原地修改顶部元素，因为修改可能破坏堆不变量。`pop()` 返回
`void`；可复制类型需要先复制到独立对象，再删除。普通只移动类型不能从这个 const 引用中
移出，标准 priority queue 因而不提供通用的只移动值提取操作；有此需求时应改用显式堆算
法或能提供提取接口的数据结构。

## 生命周期与异常

观察引用遵循底层容器操作的失效规则；默认 vector 增长可能重分配，`pop()` 也会使指向被
删元素的引用失效。比较器、元素移动/复制和分配都可能抛出异常，保证取决于底层操作与元
素类型。

## 示例

“最高值优先”确认默认最大堆语义；“任务调度”使用显式比较器处理业务优先级，并加入名称
次级排序，使等优先级结果也保持确定性。

## 常见错误

- 认为默认 top 是最小元素。
- 把比较器写成 `<=`，破坏严格弱序。
- 假设等优先级元素保持插入顺序。
- 尝试修改 `top()` 返回的对象。
- 需要任意删除或更新优先级，却继续强行使用受限适配器。

## 与 JavaScript 的区别

JavaScript 标准内建对象没有直接对应的优先队列；通常要自行实现或引入库。C++ 适配器提
供标准堆语义，但不包含并发安全、任务取消和优先级更新协议。
