# `std::vector`

`std::vector` 是连续存储、可动态扩容的序列容器，通常是需要可增长数组时的首选。

## 快速信息

- 头文件：`<vector>`
- 命名空间：`std`
- 标准：C++98 起
- 元素存储：`T` 不是 `bool` 时连续

## 什么时候使用

需要按索引访问、缓存友好的顺序遍历、保存运行时数量的同类对象，或与要求连续内存的
接口交互时使用。若元素数量在编译期固定，优先比较 `std::array`；若主要操作发生在
序列两端并且需要保留既有元素引用，应比较 `std::deque`。频繁在中间插入时，还应评估
移动后续元素的线性代价。

`std::vector<bool>` 是单独规定的空间优化特化，其元素访问不提供普通 `bool&` 语义，
也不能把它当作普通连续 `bool` 数组交给指针接口，详见
[`[vector.bool]`](https://eel.is/c++draft/vector.bool)。

## 声明

```cpp
template<class T, class Allocator = std::allocator<T>>
class vector;
```

## 模板参数

- `T`：容器保存的元素类型，必须满足所使用操作对应的元素类型要求。
- `Allocator`：负责分配和释放底层存储的分配器类型，默认是 `std::allocator<T>`。

## 复杂度

按索引访问为常数复杂度；尾部追加通常为均摊常数复杂度；在中间插入或删除通常为线性复杂度。

## 生命周期与失效规则

扩容会使指向元素的迭代器、指针和引用全部失效。未扩容的操作仍需按具体成员函数规则判断失效范围。

## 异常与约束

具体要求取决于所调用的构造函数或成员函数。使用默认分配器时，内存分配失败通常抛出 `std::bad_alloc`；自定义分配器可以有不同的失败行为。元素构造、移动、复制或比较产生的异常按对应操作的异常保证传播。

## 常见错误

- 把 `reserve(n)` 当成创建 n 个元素；它只请求容量，`size()` 不因此改变。
- 保存元素指针、引用或迭代器后继续执行可能扩容的操作，再访问旧观察位置。
- 用 `operator[]` 期待越界检查；需要报告越界时应选择 `at()`。
- 把中间插入当成常数时间，忽略后续元素移动与观察位置失效。
- 假定 `vector<bool>` 的元素就是普通 `bool&`，或能取得连续的 `bool*`。

## 与 JavaScript 的区别

它在用途上接近 JavaScript `Array`，但元素类型固定，普通特化保证连续存储，而且引用和
迭代器可能因扩容失效。JavaScript 引用对象元素时由运行时保持对象身份；C++ 代码若保存
vector 内部地址，必须同时证明期间没有触发对应的失效规则。
