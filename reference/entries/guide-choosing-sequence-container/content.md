# 选择顺序容器

顺序容器按元素位置组织数据。工程代码中先写清访问和修改模式，再选择最能直接
表达这些约束的容器。

## 默认选择

大多数可增长序列从 `std::vector` 开始：它连续存储、支持常数时间随机访问，并且
能直接交给需要连续范围的接口。缓存局部性往往也使遍历表现良好。

## 何时重新评估

- 频繁在两端插入或移除，并且不要求整体连续存储时，评估双端序列容器。
- 必须在已知位置频繁插入，且引用稳定性比随机访问和局部性更重要时，再评估链式
  容器。
- 元素数量固定且编译期已知时，评估固定大小的数组类型。

## 失效规则

vector 扩容会使指向旧存储的迭代器、指针和引用失效。即使没有扩容，插入或删除
位置之后的迭代器也可能失效。保存迭代器跨越修改前必须核对具体操作规则。

## 决策顺序

1. 是否需要连续存储或随机访问？
2. 修改主要发生在哪些位置？
3. 是否保存跨修改的引用或迭代器？
4. 元素数量和性能问题是否经过测量？

## 常见陷阱

不要仅凭“大 O 更好”选择链表。节点分配、额外指针和缓存不连续也会影响实际
成本；以真实数据规模和性能测量验证特殊选型。
