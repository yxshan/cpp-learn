# `std::deque`

`std::deque` 是支持随机访问，并能高效修改首尾的序列容器。它通常采用分段存储，
标准不把它归类为连续容器。

## 快速信息

- 头文件：`<deque>`
- 命名空间：`std`
- 标准：C++98 起
- 迭代器：随机访问，但元素不保证连续

## 代表性声明

```cpp
namespace std {
template<class T, class Allocator = std::allocator<T>>
class deque;
}
```

## 什么时候使用

需要在序列首尾频繁加入或移除元素，同时仍需按索引访问时使用。任务队列、双端待处理区和
固定长度的最近记录窗口是常见场景。需要把全部元素传给连续内存接口时不应选择它；只在
末尾增长且重视连续遍历时，先比较 `std::vector`。

## 复杂度

在任一端插入或删除单个元素为常数复杂度。中间插入和删除为线性复杂度；一般插入
成本还与插入数量和到较近一端的距离有关。

## 生命周期与失效规则

在首尾插入会使所有迭代器失效，但指向原有元素的引用仍有效。中间插入会使所有
迭代器和引用失效。删除首元素且该元素不是末元素时，只使被删元素的句柄失效；删除
末元素还会使旧尾后迭代器失效；严格在中间删除会使所有元素迭代器、引用及尾后迭代器
失效，完整规则见 [`[deque.modifiers]`](https://eel.is/c++draft/deque.modifiers)。

## 异常与前置条件

`at(n)` 越界时抛出 `std::out_of_range`。下标访问要求索引有效，`front()`、
`back()`、`pop_front()` 和 `pop_back()` 要求容器非空。首尾单元素插入抛异常时
没有效果；其他插入的保证还取决于元素复制、移动和赋值操作。

## 常见错误

不要把随机访问误解为连续内存。`std::deque` 没有 `data()`，不能用
`&values[0]` 和 `size()` 把整个容器当作一段连续缓冲区。还应区分引用与迭代器：
首尾插入后，前者可以有效而后者已经失效。

## 相关内容

`std::vector` 提供连续存储；序列容器选择指南比较两者的适用场景。
