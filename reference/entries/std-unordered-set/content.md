# `std::unordered_set`

`std::unordered_set<Key>` 使用哈希组织唯一值，重点是成员查询而不是遍历顺序。它提供平均
常数复杂度的查找、插入和删除，但最坏情况仍可能为线性。

## 快速信息

- 头文件：`<unordered_set>`
- 命名空间：`std`
- 标准：C++11 起
- 结构：唯一值、无序关联容器

## 什么时候使用

权限集合、已处理 ID、缓存键等只关心“是否存在”的场景适合 unordered set。如果输出顺
序、范围查询、最小值或可预测的最坏复杂度更重要，应评估 `std::set`。若键空间很小且连
续，也可用位图或布尔数组表达成员关系。

## 代表性声明

```cpp
template<class Key,
         class Hash = std::hash<Key>,
         class Pred = std::equal_to<Key>,
         class Allocator = std::allocator<Key>>
class unordered_set;
```

`Hash` 与 `Pred` 必须协同：任何被 `Pred` 判为相等的两个键必须产生相同哈希值。反过来，
哈希碰撞不表示键相等，容器仍会调用等价谓词区分它们。

## 桶、负载因子与复杂度

元素分布在桶中。`load_factor()` 是元素数与桶数之比，`max_load_factor()` 影响容器何时重
哈希；`reserve(n)` 请求为至少 n 个元素准备合适桶数。平均查找、插入和删除为常数复杂
度，最坏情况为线性，不应把哈希表描述成无条件 O(1)。

遍历顺序未作稳定排序保证，也可能在重哈希后改变。需要确定性输出时应读取明确键、复制
后排序，或选用有序容器；不要把当前机器上的桶顺序写入协议或测试期望。

## 返回值、失效与异常

`insert` 返回位置和是否插入。C++20 的 `contains` 直接返回布尔值；`find` 则在命中时提
供迭代器。

重哈希会使迭代器失效，但不会使元素的指针和引用失效。删除使指向被删元素的迭代器和观
察位置失效。插入是否触发重哈希取决于新大小与负载阈值；需要保留迭代器时应提前规划，
但仍不能在显式重哈希后继续使用旧迭代器。

哈希、相等比较、分配和键构造均可能抛出异常。单元素插入中，哈希函数之外的操作抛出异
常时容器不产生插入效果；哈希函数抛出是这项通用保证的明确例外，不能概括成无条件事务
回滚。自定义哈希与等价函数必须在元素存活期间保持一致语义。

多个线程可以并发读取同一容器；共享容器上的插入、删除、rehash 等结构修改以及冲突访问
需要由调用方在外部同步。平均常数查询并不意味着容器自动提供并发哈希集合语义。

## 示例

“成员检查”只查询显式键，不依赖遍历顺序；“请求 ID 去重”检查 `insert` 返回的布尔值，
并仅输出输入顺序和最终大小，因此结果可重复验证。

## 常见错误

- 断言遍历顺序，或把它当成插入顺序。
- 自定义等价谓词，却没有让相等键得到相同哈希。
- 保存迭代器后插入大量元素，忽略可能发生的重哈希。
- 把平均常数复杂度写成最坏情况保证。
- 需要范围查询时仍使用哈希集合并手工扫描全部元素。

## 与 JavaScript 的区别

JavaScript `Set` 保留插入顺序；`std::unordered_set` 不承诺这种遍历语义。C++ 还允许选择
哈希器、等价谓词和分配器，也要求调用者管理迭代器与引用生命周期。

## 相关内容

需要有序成员时阅读 `std::set`；需要为键保存值时阅读 `std::unordered_map`。
