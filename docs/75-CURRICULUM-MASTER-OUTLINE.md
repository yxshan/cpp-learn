## 1. 这份文档解决什么

`LEARNING_PLAN.md` 给出的是**时间与节奏**（阶段、周投入、作品、验收），本文给出的是**能力分类与门槛口径**：一个 C++ 后端/基础架构方向的实习生至少要会什么、这些能力如何分类、按什么顺序获得、哪些由这个平台承载、哪些必须由外部课程承载。

它先于内容生产：任何新 activity 都应能回答"它属于哪一类、补的是门槛还是方向"。

**两个必须说清的结论：**

1. **门槛比行业综述低得多。** 字节的门槛表述只有三条实质要求：精通至少一门语言、掌握扎实的计算机基础知识（数据结构、算法、操作系统）、有逻辑分析与拆分能力。腾讯云那篇的"协程 / io_uring / 内存池 / 缓存行 / 服务网格"是**中级到资深**要求。把后者当前者，会得到一个永远准备不完的总纲。
2. **门槛里没有一项是"某门语言的冷知识"。** 三条要求中两条是计算机基础与算法。这直接决定了课程重心的分配。

## 3. 分层口径

| 层 | 含义 | 判定 |
|---|---|---|
| **门槛层** | 缺任何一项，实习简历过不了或面试第一轮就崩 | 逐条有可判定验收（见 §5） |
| **方向层** | 决定你去后端、基础架构、客户端还是游戏，决定薪资档位 | 到阶段 3 再选择，不提前投入 |

## 4. 六类能力

每类给出：学到什么 → 门槛验收 → 平台现有覆盖 → 缺口。

### C1 语言与标准库

**学到什么**：值/引用/指针语义、`const`、作用域与生命周期、类与不变量、RAII、拷贝与移动、智能指针、STL 容器/迭代器/算法、模板与 concepts、现代词汇（lambda、`optional`、`variant`、ranges）、异常与错误处理。

**门槛验收**：能独立写出 500–1500 行、多文件、有测试的 C++20 程序；AddressSanitizer 干净；能逐行解释每个对象的**所有者、借用者、生命周期**。

**平台覆盖**：22 个活动（560 分钟）+ 4 个语言类练习，配了概念卡（[心智模型](reference/MODERN_CPP_MENTAL_MODEL.md)、[所有权与生命周期](reference/OWNERSHIP_AND_LIFETIME.md)）。

**缺口**：对全部 activity 与 lesson 正文做关键词检索后确认，以下语言主题**在教学层面为零**——它们只在别的课程里被顺带提过，没有独立课程：

| 主题 | 检索结果 | 计划是否要求 |
|---|---|---|
| `std::string` / 文本处理 | 0 | 阶段 1 明确列出"字符串" |
| 枚举 `enum class` | 0 | 阶段 1 明确列出"枚举" |
| 异常机制 | 2（仅顺带提及） | 阶段 1"异常的基本认识"、阶段 2"错误处理" |
| 错误处理（`expected`/`error_code`/`noexcept`） | 0 | 阶段 2"错误处理" |
| 继承与多态 | 0 | 阶段 2"组合与继承" |
| 初始化与窄化 | 0 | 计划未列，但属 JS→C++ 头号陷阱 |
| 隐式/显式类型转换 | 0 | 计划未列 |
| 运算符重载与比较 | 0 | 计划未列 |

另有一处配置缺口：sanitizer 只挂在最早的 4 个活动上，`classes-and-raii`、`copy-move-ownership` 与两个所有权练习都不跑 ASan——而这正是最容易出错的地方。C1-1 批次已关闭第一行。

### C2 工程化工具链

**学到什么**：编译/链接/头文件与源文件、CMake 与 CTest、Git 工作流、单元测试、调试器、静态分析、sanitizer、格式化、性能剖析。

**门槛验收**：干净目录下一条命令完成构建与测试；CI 通过；能用调试器定位越界；能用剖析工具指出一次性能回归的成因。

**平台覆盖**：5 个活动（170 分钟）——`cmake-testing-debugging`、`cmake-ctest-review`、`engineering-diagnostics`。

**缺口**：基本够用。真正要补的是把 sanitizer 覆盖扩到 C1 的内存主题（见上），属于配置而非新内容。

### C3 数据结构与算法

**学到什么**：复杂度分析与增长比、数组与字符串、哈希表、栈与队列、排序与二分；链表、树、堆、图基础、递归、回溯、动态规划入门。

**门槛验收**：能独立完成中等难度算法题（约 40 分钟/题）并说明时间与空间复杂度；能解释为什么某条 SQL 或某个容器操作是这个复杂度。

**平台覆盖**：7 个活动（235 分钟）——排序性质、复杂度增长、哈希索引不变量，加 `sorted-unique`。**只有排序、哈希、复杂度三块。**

**缺口（最大）**：链表、树、堆、图、递归、回溯、动态规划、二分查找**全部为零**（对 70 个 activity 与 lesson 正文做过关键词检索确认）。而 `LEARNING_PLAN` 给算法分配每周 1.5 小时、贯穿阶段 1 到阶段 3，`MISSION.md` 也把"能通过常见代码题"写进验收。这是课程与计划之间最大的一处不一致。

### C4 计算机系统基础

**学到什么**：进程/线程/虚拟内存/文件与系统调用；TCP/IP、DNS、HTTP；关系模型、SQL、索引与事务；Linux 常用命令与排障。

**门槛验收**：能从浏览器输入 URL 讲到数据落库的完整路径；能解释进程、线程、协程的区别与代价；能解释一条 SQL 命中或不命中索引的原因；能用 `strace`/`top`/日志定位一次人为故障。

**平台覆盖**：16 个活动（515 分钟）——文件与子进程、loopback socket 与最小 HTTP、SQLite 事务、查询计划、虚拟内存与观测工具、UDP 与事件循环、缓存一致性。**全部是应用层动手实验**，配一张[本地系统实验](reference/LOCAL_SYSTEM_LABS.md)资源表。

**缺口**：**理论深度不在平台能力范围内**。平台的 Judge 只能验证程序行为，无法验证"你是否理解三次握手"或"虚拟内存如何映射"。这部分必须由外部课程承载（见 §6），平台只负责让概念落地成可运行实验。

### C5 并发与性能

**学到什么**：线程与共享状态、原子操作与内存序、锁与死锁、条件变量、线程池、协作取消与有界关闭、负载测试与可观测性、性能测量而非猜测。

**门槛验收**：能写出无数据竞争的多线程服务，并用负载测试给出延迟与吞吐；能解释一致性取舍与失败场景。

**平台覆盖**：7 个活动（235 分钟）——线程与原子、任务队列与取消、内存模型与死锁、生产就绪。

**缺口**：覆盖合理。可补的是把性能检查（目前 6/70 使用）用到更多并发活动上。

### C6 项目与表达

**学到什么**：把一个需求拆成模块与接口；用 Git 讲清演进；写 README 与设计说明；在追问下解释设计取舍。

**门槛验收**：两个可展示项目，其中一个是可部署网络服务；能逐行解释自己的代码并现场修改；能回答"为什么这样设计""哪里会失败"。

**平台覆盖**：5 个项目、11 个里程碑（900 分钟），是本课程投入最大的一块，且都带教师评语要求。

**缺口**：项目形态齐全，缺的是**面试表达的训练闭环**（模拟追问、限时讲设计）。`LEARNING_PLAN` §5 的 AI 规则已写了协议，但平台没有对应活动。

## 5. 起码要求（门槛清单）

以下每条都写成可判定的形式，避免"感觉学会了"。

| # | 类别 | 门槛（缺一项即未达标） |
|---|---|---|
| 1 | 语言 | 独立完成 500–1500 行多文件 C++20 项目；ASan/UBSan 干净；能解释所有权与生命周期 |
| 2 | 工程 | 一条命令构建 + 测试；CI 通过；有 README；能用调试器定位越界 |
| 3 | 算法 | 中等题 40 分钟内独立完成，并说清复杂度 |
| 4 | 系统 | 讲清一次请求从 socket 到落库的路径；解释进程/线程/协程；解释索引命中 |
| 5 | 并发 | 无数据竞争的多线程服务 + 负载测试的延迟/吞吐数字 |
| 6 | 项目 | 两个可展示项目；其中一个可部署网络服务 |
| 7 | 表达 | 能逐行解释项目代码并现场修改；能回答失败场景与取舍 |

## 6. 时间顺序

按 `LEARNING_PLAN.md` §0 的时间约束，不新增承诺。

| 段 | 时间 | 投入 | 主攻 | 出口验收 |
|---|---|---|---|---|
| 0 | 现在 – 2027.6 | 无硬任务 | 考研优先；每月 1–2 次 45 分钟轻量接触 | 无 |
| 1 | 2027.7 – 9 | 12–15 h/周 | C1 语言 + C2 工程化 + C3 起步（复杂度、数组/字符串、哈希、栈/队列、排序、二分）+ C4 起步 | 门槛 1、2 达标；一个命令行项目 |
| 2 | 2027.10 – 2028.3 | 8–10 h/周 | C3 完整（链表、树、堆、图、递归、回溯、DP）+ C4 完整（OS/网络/DB 理论 + 平台实验）+ C5 | 门槛 3、4、5 达标 |
| 3 | 2028.3 + | 按实习节奏 | C6 项目深化 + 面试表达 + 方向选择（C++ 后端/基础架构 vs 补 Go vs 客户端） | 门槛 6、7 达标；简历与模拟面试 |

**平台的承载边界（关键设计决定）**：段 1 与段 2 的**动手验证**由平台做；段 2 的**理论深度**由外部课程做。对照关系：

| 类别 | 外部课程参照（来自 [csdiy](https://csdiy.wiki/)） | 平台负责 |
|---|---|---|
| C3 算法 | MIT 6.006 / 6.046、UCB CS61B / CS170 | 把算法写成可判题程序；用性质测试与性能检查验证 |
| C4 系统 | CMU 15-213 CSAPP、MIT 6.S081、Stanford CS144、CMU 15-445 | 文件/进程/socket/SQLite/内存映射实验 |
| C5 并发 | CMU 15-418 / Stanford CS149、（进阶）MIT 6.824 | 线程池、取消、锁顺序、负载测试 |

理由：平台的判题能力只能验证**程序行为**，不能验证**理解**。把理论塞进 activity 会得到"能跑但没懂"的假验收。

## 7. 现状量化

按主题把 72 个 activity 归类（划分是我做的，非权威），合计 44.1 小时：

| 类别 | 活动 | 时长 | 占比 |
|---|---:|---:|---:|
| C1 语言与标准库 | 26 | 620 分钟 | 23% |
| C2 工程化工具链 | 5 | 170 分钟 | 7% |
| C3 数据结构与算法 | 7 | 235 分钟 | 9% |
| C4 计算机系统基础 | 16 | 515 分钟 | 20% |
| C5 并发与性能 | 7 | 235 分钟 | 9% |
| C6 项目与表达 | 11 | 900 分钟 | 34% |

对照 §5 的门槛清单，**7 条门槛里有 3 条（算法、系统理论、面试表达）目前没有对应内容**，而这 3 条恰好都在门槛的高权重位置。C6 占三分之一时长，是当前课程最厚的部分，也最容易在生产时被高估价值——项目要能讲清楚才有用。

## 8. 待决策

1. **算法主线是否作为下一个内容批次**（约 12–15 个主题、24–30 个 activity、12–15 小时）。它是 §7 里最大的缺口，且正好用上平台目前闲置的能力：性质测试（现 2/70）验证算法正确性，性能检查（现 6/70）验证复杂度断言。
2. **C4 系统理论的外包清单**：是否接受"平台只做实验、理论交给外部课程"这一边界？若接受，需要在本文补一张逐主题的课程映射表。
3. **C6 的面试表达闭环**是否要做进平台，还是留在平台外按 `LEARNING_PLAN` §5 的 AI 协议人工执行。
4. **门槛是否要调整**：本文按"大厂实习生"定门槛。若目标改为"中小厂实习"，软件工程与系统理论的要求可整体下调一档（对照 §2 的第二条来源）。
