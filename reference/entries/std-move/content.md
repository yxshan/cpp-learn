# `std::move`

`std::move` 把表达式显式转换为引用同一对象的 xvalue，使后续重载决议可以选择移动构造或移动
赋值。它只是 cast helper，本身不移动、清空或销毁对象。

## 快速信息

- 头文件：`<utility>`
- 命名空间：`std`
- 标准：C++11 起；C++14 起 `constexpr`
- 返回：引用同一对象的 rvalue reference

## 什么时候使用

一个仍有名字的对象即将交给消费型 API，并且后续代码不再依赖它的旧值时使用。例如把
`unique_ptr` 的所有权交给另一个变量，或把大型值放入容器。

不要给每个 return 表达式机械添加 `std::move`；它可能妨碍复制消除或 NRVO。若只是传递一个
泛型包装器收到的 forwarding reference，应使用 `std::forward<T>` 保留调用者值类别。

## C++20 代表声明

```cpp
template<class T>
constexpr std::remove_reference_t<T>&& move(T&& value) noexcept;
```

这里的 `value` 是便于解释的参数名。标准规定的效果等价于
`static_cast<std::remove_reference_t<T>&&>(value)`。

## 参数与前置条件

`value` 可以由 lvalue 或 rvalue 绑定；模板推导后，返回类型先移除 `T` 中的引用，再加上
`&&`。对象必须仍处于生命周期内，但其类型不必真的提供移动构造函数。

对 const 对象调用会产生 `const T&&`。常见移动构造接受非 const `T&&`，因此后续构造往往只能
选择复制；`std::move` 不能移除 const。

## 返回值与值类别

返回引用同一对象的 xvalue，不创建新对象也不取得所有权。单独写 `std::move(value);` 后丢弃
结果，不会调用任何移动操作；只有消费返回表达式的构造、赋值或函数调用才可能真正转移资源。

## 复杂度

标准没有为该 helper 单列渐进复杂度。它的规定效果只是一次类型转换，不遍历对象，也不进行
分配；后续被选择操作的成本不属于 `std::move` 自身。

## 异常与错误

`std::move` 无条件 `noexcept`。后续移动或复制构造仍可按目标类型合同抛异常。把返回引用保存到
原对象生命周期之外不会产生可捕获错误，而会形成悬空引用。

## 生命周期与移动后状态

返回引用不延长原对象生命周期。若后续操作真正移动了标准库对象，除非具体类型另有规定，源
对象通常仍有效但值未指定：可以析构、重新赋值，并只能执行其合同允许的操作。用户类型的移动
后状态由自身设计决定；不能笼统声称“move 后一定为空”。

对临时量使用 `std::move` 并把结果绑定到更长寿命的引用，也不会延长临时量的生命周期。

## 线程安全

`std::move` 这次引用转换本身不读取或修改对象的存储值，也不建立线程同步。返回结果仍别名同一
对象；若一个线程随后通过该引用写对象，同时另一个线程无同步地读写同一内存位置，仍会形成
数据竞争。把表达式转换成 xvalue 不会让被引用对象自动具备线程安全性。

## 常见错误

- 认为调用本身已经移动或清空对象。
- 在移动后读取类型没有保证的旧值。
- 对 const 对象使用后惊讶于发生复制。
- 在 return 中无条件添加 `std::move`，破坏复制消除机会。
- 保存指向临时量的 move 结果并跨越完整表达式使用。
- 与 `<algorithm>` 中接收三个迭代器的范围 `std::move` 混淆。

## 与 JavaScript 的区别

> JavaScript 变量通常复制 GC 管理的对象引用，没有 xvalue、移动构造或 moved-from 状态。
> “把资源句柄交给消费型 API”可以帮助理解意图，但 JS 赋值本身不会通过 cast 选择另一组重载。
