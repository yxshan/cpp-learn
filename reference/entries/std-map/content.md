# `std::map`

`std::map<Key, T>` 保存“键到值”的唯一映射，并按照比较器定义的键顺序遍历。它适合既需要
按键查找，又需要稳定排序、最小/最大键或范围查询的场景。

## 快速信息

- 头文件：`<map>`
- 命名空间：`std`
- 标准：C++98 起
- 结构：唯一键、有序关联容器

## 什么时候使用

需要按键排序输出、查找第一个不小于目标的键，或希望插入后已有元素的引用保持有效时，
优先考虑 `map`。如果只需要平均常数时间的精确键查询且不关心顺序，通常先评估
`std::unordered_map`；如果键是连续的小整数，`vector` 往往更直接。

## 代表性声明

```cpp
template<class Key, class T, class Compare = std::less<Key>,
         class Allocator = std::allocator<std::pair<const Key, T>>>
class map;
```

常用操作包括 `find`、`contains`（C++20）、`lower_bound`、`insert`、`try_emplace`、
`insert_or_assign`、`operator[]` 和 `erase`。`value_type` 是 `pair<const Key, T>`，已经进入
容器的键不能通过迭代器直接修改，否则会破坏排序不变量。

## 键比较与等价

键的唯一性由比较器定义，而不是必须调用 `operator==`。当 `comp(a, b)` 与
`comp(b, a)` 都为 `false` 时，两键等价。比较器必须形成严格弱序；带状态比较器的状态也
属于容器排序规则的一部分。

`operator[]` 在键不存在时插入一个值初始化的 `T`，因此它要求映射值能完成相应构造，
也会把只读查询变成写操作。只查询时使用 `find`、`contains` 或 `at`；要避免先默认构造再
赋值时使用 `try_emplace` 或 `insert_or_assign`。

## 返回值与复杂度

`find` 返回匹配元素的迭代器，未命中时返回 `end()`。唯一键的 `insert`/`emplace` 返回
`pair<iterator, bool>`，布尔值说明本次是否插入。查找、插入和按键删除通常保证对数复杂
度；使用正确位置提示的插入可能达到摊销常数复杂度。

遍历按比较器顺序进行，但标准不规定内部必须是红黑树。不要把一种实现策略当作接口
保证。

## 生命周期、失效与异常

插入和 `emplace` 不使已有迭代器、指针和引用失效。删除只使指向被删元素的观察位置失
效；提取节点同样结束该元素在原容器中的关联。容器销毁后全部观察位置失效。

比较器、分配器、键或值的构造都可能抛出异常。单元素 `insert`/`emplace` 中的操作抛出
异常时，容器不产生插入效果。不要让比较器依赖会在元素仍位于容器时变化的外部状态。

标准容器允许不同线程并发修改不同元素中的 mapped value；但对容器结构的修改、对同一元
素的冲突访问，以及结构修改与可能观察该结构的操作仍需同步。不要把这一元素级例外理解
成 map 整体具有线程安全的写接口。

## 示例

“有序库存”展示键唯一性、`operator[]` 更新和按键遍历；“延迟聚合”展示按路径建立统计
值，并利用 map 顺序产生确定性报告。两个示例都由本地 C++20 工具链运行验证。

## 常见错误

- 用 `operator[]` 检查键是否存在，意外插入空值。
- 修改决定键排序的外部状态，令比较器不再保持严格弱序。
- 认为所有键查找都是 O(1)，或认为标准强制使用红黑树。
- 需要重复键却使用 `map`；这种场景应评估 `multimap` 或把多个值放进映射值容器。
- 删除元素后继续使用指向该元素的迭代器或引用。

## 与 JavaScript 的区别

JavaScript 的 `Map` 保留插入顺序；`std::map` 按键比较器排序。C++ 映射还把键和值类型、
分配和对象生命周期放入静态类型与容器契约中。

## 相关内容

只保存唯一有序值时阅读 `std::set`；不需要顺序时比较 `std::unordered_map`。对已排序范围
做二分定位时阅读 `std::lower_bound`。
