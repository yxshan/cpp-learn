# `std::set`

`std::set<Key>` 保存按比较器排序的唯一值。元素本身就是键，因此它适合成员集合、去重后
的有序输出和按值范围查询。

## 快速信息

- 头文件：`<set>`
- 命名空间：`std`
- 标准：C++98 起
- 结构：唯一值、有序关联容器

## 什么时候使用

当“是否属于集合”与“按顺序遍历或查范围”同样重要时使用 `set`。若只需哈希成员查询且
不关心顺序，优先比较 `std::unordered_set`；若数据很少、主要批量构建后读取，排序后的
`vector` 可能拥有更好的局部性和更低的节点开销。

## 代表性声明

```cpp
template<class Key, class Compare = std::less<Key>,
         class Allocator = std::allocator<Key>>
class set;
```

常用操作是 `insert`、`emplace`、`find`、`contains`、`lower_bound`、`upper_bound`、
`equal_range` 和 `erase`。set 迭代器只允许把元素当作 `const Key` 观察；若能原地修改键，
容器顺序会被破坏。

## 唯一性与范围

与 `map` 一样，唯一性由比较器等价关系定义：两个方向都不“小于”时视为同一个键。
比较器必须形成严格弱序。

`lower_bound(value)` 返回第一个“不小于 value”的元素，`upper_bound(value)` 返回第一个
“大于 value”的元素。二者组成的半开区间可以表达有序范围；对于唯一键，其长度至多为
一。

## 返回值、复杂度与失效

唯一键插入返回 `pair<iterator, bool>`。查找、插入和按键删除通常为对数复杂度；完整遍历
仍是线性复杂度。

插入不使已有迭代器、引用和指针失效。删除只使指向被删元素的观察位置失效。不要将“节
点通常稳定”扩大成“任何操作后都永久有效”；容器销毁、被删元素以及不兼容的交换/移动
场景仍需按各自契约判断。

## 异常与并发

比较、分配和元素构造可能抛出异常。单元素 `insert`/`emplace` 中的操作抛出异常时，容器
不产生插入效果。比较器不应修改容器可观察状态，也不应依赖会破坏排序关系的可变数据。
多个线程可并发读取同一容器，但结构修改与冲突访问仍需要同步。

## 示例

“唯一端口”展示去重与自然升序遍历；“选择版本范围”使用成员 `lower_bound` 和
`upper_bound` 选择闭区间语义对应的半开迭代器范围。

## 常见错误

- 试图通过迭代器修改 set 元素。
- 使用不满足严格弱序的比较器，例如用 `<=` 代替 `<`。
- 认为 `set` 保留插入顺序。
- 只做一次去重，却忽略排序加 `unique` 或哈希集合可能更符合数据流。
- 把 set 成员 `lower_bound` 与通用算法混淆；成员操作能利用容器结构。

## 与 JavaScript 的区别

JavaScript `Set` 按插入顺序迭代；`std::set` 按比较器排序，并且所有元素具有同一静态类
型。C++ 中修改、删除和观察位置还有明确的对象生命周期约束。

## 相关内容

需要键值对时阅读 `std::map`；不需要排序时阅读 `std::unordered_set`；对普通已排序范围
定位时阅读 `std::lower_bound`。
