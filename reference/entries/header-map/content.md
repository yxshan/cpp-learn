# `<map>`

`<map>` 声明按键比较器排序的键值关联容器：唯一键的 `std::map` 与允许等价键重复的
`std::multimap`，以及它们的非成员操作。

## 快速信息

- 头文件：`<map>`
- 命名空间：`std`
- 首次标准：C++98
- 核心选择：键是否唯一、是否需要按键顺序和范围查询

## 什么时候包含

源文件只要直接声明 map/multimap、使用对应 `std::erase_if` 或相关比较/交换接口，就应显式
`#include <map>`。不要依赖某个框架头文件、`<set>` 或其他容器碰巧传递包含它；标准只保证
在引入适当头文件后使用实体。

## 头文件中的主要实体

| 实体组 | 作用 | 版本提示 |
|---|---|---|
| `std::map<Key, T>` | 每个比较器等价键最多一个映射值 | C++98 |
| `std::multimap<Key, T>` | 允许多个比较器等价键 | C++98 |
| `std::pmr::map`、`std::pmr::multimap` | 使用多态分配器的别名 | C++17 |
| 比较运算与 `std::swap` | 比较或交换完整容器 | 比较/交换自 C++98，三路比较自 C++20 |
| `std::erase_if` | 按谓词从容器中删除元素 | C++20 |

当前 Working Draft synopsis 还会显示晚于 C++20 的范围构造或插入接口；本项目 C++20 示例
不使用这些未来能力。

## 关键选择边界

map 的遍历由 `Compare` 排序，不保留插入顺序。键唯一性同样由比较器等价关系决定，而不是
必须调用 `operator==`。`multimap` 允许等价键，因此 `find` 只给出其中一个位置；要处理全
部等价键应使用 `equal_range`。

只做平均常数精确查询且不关心顺序时，应比较 `<unordered_map>`。只保存键而没有映射值
时，转到 `<set>`。

## 头文件边界

`<map>` 不声明通用二分算法或排序算法；相关操作来自 `<algorithm>`。容器成员
`lower_bound` 能利用内部索引，通常比对 map 迭代器调用通用 `std::lower_bound` 更合适。

## 常见错误

- 认为 map 按插入顺序遍历。
- 需要重复键却使用 `operator[]` 覆盖唯一键值。
- 依赖其他头文件传递包含 `<map>`。
- 把当前 draft 的未来范围接口误标为 C++20。
- 用通用 lower_bound 扫描树迭代器，却忽略成员查找。
