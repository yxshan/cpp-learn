# `std::vector::reserve`

`reserve(n)` 请求 `std::vector` 至少准备容纳 `n` 个元素的容量，但不会创建元素，
也不会改变 `size()`。

## 快速信息

- 头文件：`<vector>`
- 所属类型：`std::vector`
- 标准：C++98 起；C++20 起可为 `constexpr`
- 复杂度：最坏线性于当前元素数量

## 代表性声明

```cpp
constexpr void reserve(size_type n);
```

以上是 C++20 形式；更早标准中的成员不带 `constexpr`。

## 行为

若 `n > capacity()`，容器重新分配，调用后容量至少为 `n`。否则不会重新分配，
容量保持不变。调用不改变 `size()`。之后的插入在新大小超过容量前不会再次引起
重新分配。

## 生命周期与失效规则

发生重新分配时，所有元素引用、指针、迭代器和尾后迭代器失效；没有重新分配时，
这些句柄保持有效。如果计划保存元素地址，应先预留足够容量，并确保后续大小不
超过容量。

## 异常与约束

`n > max_size()` 时抛出 `std::length_error`，分配失败也可以抛出分配器异常。
元素需满足移动插入要求。除不可复制元素的抛异常移动构造这一特殊情况外，异常
通常不改变 vector。

## 示例

示例先证明 `reserve(3)` 后大小仍为零，再追加三个元素。只断言
`capacity() >= 3`，因为标准不要求容量恰好等于请求值。

## 常见错误

`reserve()` 不是 `resize()`；对只预留容量的空 vector 使用 `values[0]` 仍然非法。
不要在每次 `push_back` 前调用 `reserve(size() + 1)`，这可能破坏容器原本的几何
增长策略，造成反复线性移动。只有能估计后续规模时才适合一次性预留。
